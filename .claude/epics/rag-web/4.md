## Technical Details
- **Architecture**: Frontend integration with existing backend API

- **Existing API**: `/api/chat/analyze` endpoint available
- **Excel Upload**: `/api/chat/upload-excel` endpoint for patient data
- **Authentication**: Map NextAuth users to business `account_id` field
- **Database**: Use existing `t_evaluation` table through API
- **Patient Data**: Support Excel upload with Polygon worksheet format (30+ measurements + clinical significance)

### t_evaluation Table Structure (Existing Business Table)
```sql
- id: AUTO_INCREMENT primary key
- rid: Treatment record ID (nullable)
- account_id: User account ID (maps to NextAuth users)
- session_id: Conversation grouping ID
- api_type: 'chat' for conversation messages
- user_message: User input (for chat api_type)
- ai_response: AI response (for chat api_type)
- model_used: AI model identifier
- input_tokens, output_tokens: Cost tracking
- created_at, updated_at: Timestamps
```

### Conversation Mapping Strategy
- **Conversations**: Each unique `session_id` = one conversation
- **Messages**: Each record with `api_type='chat'` = one message pair
- **User Association**: `account_id` links to NextAuth user mapping
- **Cost Tracking**: Built-in token counting for business analytics
